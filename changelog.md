## v2.0.0 - 2026-04-03
* The `GetWheelchairUse()` accessor method has been removed from both `ClientFacingActivity` and `ClientFacingProfile`. Existing callers of these methods will encounter a compile error. To migrate, replace any calls to `obj.GetWheelchairUse()` with direct field access via `obj.WheelchairUse`.
* Three new query expression types are now available: `DerivedReadinessColumnExpr` (for readiness columns such as sleep score, recovery score, and strain zone), `AwakeningsValueMacroExpr` (value macro for awakenings), and `InsulinInjectionTimeseriesExpr` (dedicated timeseries expression replacing the previous `insulin_injection` value in `IntervalTimeseriesExpr`). The `AggregateExprArgVisitor`, `QueryGroupByItemVisitor`, and `QuerySelectItemVisitor` interfaces each gain three new required `Visit*` methods; existing implementations must add `VisitDerivedReadinessColumnExpr`, `VisitAwakeningsValueMacroExpr`, and `VisitInsulinInjectionTimeseriesExpr`. The `Placeholder` struct's exported `Placeholder` field and its `GetPlaceholder`/`SetPlaceholder` methods have been removed — `placeholder` is now an internal literal always serialized as `true`.
* **Breaking changes** to lab report parsing types:
* `ParsingJob.JobId` field and its `GetJobId()`/`SetJobId()` methods have been removed. A new `FailureReason *ParsingJobFailureReason` field (with `GetFailureReason()`/`SetFailureReason()` methods) and the `ParsingJobFailureReason` enum (`InvalidInput`, `LowQuality`, `NotEnglish`) have been added in its place.
* `ResultMetadata` fields `PatientFirstName`, `PatientLastName`, `Dob`, and `LabName` have changed from `string` to `*string`. Callers must now dereference these values and pass pointers to the corresponding `Set*` methods.
* A new optional `Gender *ResultMetadataGender` field (with the `ResultMetadataGender` enum) has been added to `ResultMetadata`.
* `BodyCreateLabReportParserJob.File` has changed from `io.Reader` to `[]io.Reader` to support multiple file uploads.
* Several breaking changes have been made to bulk operation request types. The `TeamId` field and `SetTeamId` method have been removed from `BulkExportConnectionsBody`, `BulkImportConnectionsBody`, `BulkPauseConnectionsBody`, `BulkTriggerHistoricalPullBody`, and `LinkListBulkOpsRequest`. The exported types `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` have also been removed — callers referencing these types or their `SetTeamId` methods must remove those usages. New additions include a `RecoveryReadinessScore` field on `ClientFacingSleep`, new `VitalIosSdkVersion`, `VitalAndroidSdkVersion`, and `GrantedPermissions` fields on `ManualConnectionData`, and new provider constants `ManualProvidersSamsungHealth` and `PasswordProvidersTandemSource`.
* The SDK now includes new types for lab report parsing job events (`ClientFacingLabReportParsingJobCreatedEvent`, `ClientFacingLabReportParsingJobUpdatedEvent`), enriched order tracking with `ClientFacingOrderTransaction`, `OrderOrigin`, `OrderLowLevelStatus`, and `OrderStatusDetail`, and structured lab result types including `BiomarkerResult`, `LabResultsRaw`, `MissingBiomarkerResult`, and `SampleData`. The `Address`, `PatientAddressCompatible`, and `ClientFacingOrder` models gain new optional fields (`access_notes`, `clinical_notes`, `last_event`, `origin`, `order_transaction`). New lab constants (`sonora_quest`, `crl`) have been added.
* Several breaking changes are included in this release:
* `UserInfo.GetAddress()` and `UserInfo.SetAddress()` now use `*UserAddress` instead of `*Address`; update any call sites accordingly.
* `UserRefreshSuccessResponse.GetSuccess()` and `SetSuccess()` have been removed; the `success` field is now an enforced literal managed internally, accessible via the new `Success() bool` method.
* `BookPscAppointment` in `LabTestsClient` now accepts `*LabTestsBookPscAppointmentRequest` instead of `*AppointmentBookingRequest`.
* New additions include `Compendium`, `LabAccount`, and `OrderTransaction` sub-clients on the top-level client, new insulin delivery detail fields (`DeliveryMode`, `DeliveryForm`, `BolusPurpose`) on `ClientFacingInsulinInjectionSample`, and a new `ClientFacingDeviceSourceTypeInsulinPump` constant.
* The SDK now includes types for lab compendium search and conversion workflows. New exported types include `SearchCompendiumBody`, `ConvertCompendiumBody`, `SearchCompendiumResponse`, `ConvertCompendiumResponse`, `CanonicalCandidate`, `PerLabCandidate`, `RelatedCandidate`, `ProviderIdConversionResponse`, along with the `CompendiumSearchLabs` and `SearchMode` enums.
* The SDK now includes two new API clients: `compendium` (with `Search` and `Convert` methods) and `labaccount` (with `GetTeamLabAccounts`). New types `ClientFacingLabAccount`, `GetTeamLabAccountsResponse`, `LabAccountDelegatedFlow`, `LabAccountStatus`, and `UsState` are available in the root package. The `insulin_pump` source type has been added to the electrocardiogram and menstrual cycle source type enums.
* The SDK now includes a new `ordertransaction` package with a `Client` that supports fetching order transaction details (`GetTransaction`), lab results (`GetTransactionResult`), and lab result PDFs (`GetTransactionResultPdf`). New types `GetOrderTransactionResponse` and `OrderSummary` have been added, along with a new `ClientFacingSleepCycleSourceTypeInsulinPump` source type constant and a `Bytes` pointer helper utility.
