## v2.0.0 - 2026-04-01
* The `GetWheelchairUse()` accessor method has been removed from both `ClientFacingActivity` and `ClientFacingProfile`. Callers that reference these methods must update their code by removing those calls or accessing the `WheelchairUse` struct field directly.
* Three new query expression types are now available: `DerivedReadinessColumnExpr` (with an 8-value `DerivedReadinessColumnExprDerivedReadiness` enum), `AwakeningsValueMacroExpr`, and `InsulinInjectionTimeseriesExpr` (with a 12-value field enum). These types are supported in `AggregateExprArg`, `QueryGroupByItem`, and `QuerySelectItem` unions, and all three visitor interfaces (`AggregateExprArgVisitor`, `QueryGroupByItemVisitor`, `QuerySelectItemVisitor`) now require implementing the corresponding `Visit*` methods.
**Breaking changes:** The `Placeholder` struct's exported `Placeholder bool` field, `GetPlaceholder()` method, and `SetPlaceholder()` setter have been removed — `placeholder` is now a private literal exposed via a `Placeholder() bool` value receiver. The `IntervalTimeseriesExprTimeseriesInsulinInjection` constant has been removed (use `InsulinInjectionTimeseriesExpr` instead). The three visitor interfaces each gained new required methods, so any custom implementations must be updated.
* **Breaking changes to `ParsingJob` and `ResultMetadata`:**
* The `JobId` field and its `GetJobId()`/`SetJobId()` methods have been removed from `ParsingJob`. A new `FailureReason` field (type `*ParsingJobFailureReason`) has been added along with a new `ParsingJobFailureReason` enum (`invalid_input`, `low_quality`, `not_english`).
* `ResultMetadata` fields `PatientFirstName`, `PatientLastName`, `Dob`, and `LabName` changed from `string` to `*string`; their corresponding setters now accept `*string`. A new `Gender` field of type `*ResultMetadataGender` has been added along with a new `ResultMetadataGender` enum (`male`, `female`, `other`).
* `BodyCreateLabReportParserJob.File` changed from `io.Reader` to `[]io.Reader`.
* The SDK now supports Sonora Quest as an appointment provider and lab (`AppointmentProviderSonoraQuest`, `ClientFacingLabsSonoraQuest`). New fields have been added to appointment booking (`AppointmentNotes`, `AsyncConfirmation`, sync/async timeout controls), order creation (`ClinicalNotes`), lab test creation (`LabAccountId`, `LabSlug`), and address types (`AccessNotes` on `PatientAddress` and `UsAddress`). New request filters include `OrderTransactionId` on `LabTestsGetOrdersRequest`, `LabSlug` on `LabTestsGetMarkersRequest`, and `AllowStale` on `LabTestsGetPscAppointmentAvailabilityRequest`. A new `LabTestsBookPscAppointmentRequest` type with idempotency key support has been added.
**Breaking change:** `AppointmentPscLabs` has been changed from a type alias (`= string`) to a named `string` type; code that assigned bare string literals to `AppointmentPscLabs` variables may need to add an explicit cast. Additionally, several types have been removed: `BiomarkerResult`, `MissingBiomarkerResult`, `LabResultsMetadata`, `LabResultsRaw`, `LabResultsRawResults`, `FailureType`, `OrderLowLevelStatus`, `ParentBiomarkerData`, `SampleData`, `ClinicalInformation`, `UtcTimestampWithTimezoneOffset`, and their associated helpers — callers referencing these types must update their code.
* The `TeamId` field and `SetTeamId` method have been removed from `BulkExportConnectionsBody`, `BulkImportConnectionsBody`, `BulkPauseConnectionsBody`, `BulkTriggerHistoricalPullBody`, and `LinkListBulkOpsRequest`. The exported types `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` have also been removed — callers referencing these symbols must remove those usages. New additions include `ManualProvidersSamsungHealth`, `PasswordProvidersTandemSource`, a `RecoveryReadinessScore` field on `ClientFacingSleep`, and new fields `VitalIosSdkVersion`, `VitalAndroidSdkVersion`, and `GrantedPermissions` on `ManualConnectionData`.
* Several breaking changes and new capabilities are introduced in this release.
**Breaking changes:**
* `UserRefreshErrorResponse.Success` is no longer a directly accessible exported field. It is now a private literal accessed via the `.Success()` method.
* `HistoricalPullCompleted.IsFinal` is no longer a directly accessible exported field. It is now a private literal accessed via the `.IsFinal()` method.
* Existing code that reads these fields directly (e.g., `resp.Success`, `completed.IsFinal`) must be updated to use the new method form.
**New capabilities:**
* New `BiomarkerResult`, `MissingBiomarkerResult`, `LabResultsRaw`, `LabResultsMetadata`, `SampleData`, `PerformingLaboratory`, and `ClinicalInformation` types for richer lab result handling.
* New `ClientFacingLabReportParsingJobCreatedEvent` and `ClientFacingLabReportParsingJobUpdatedEvent` webhook event types.
* New `ClientFacingOrderTransaction` and `ClientFacingOrderInTransaction` types; `ClientFacingOrder` now includes `LastEvent`, `OrderTransaction`, `ClinicalNotes`, and `Origin` fields.
* `Address`, `PatientAddressCompatible`, and `PatientAddressWithValidation` now include an `AccessNotes` field.
* New `OrderStatusDetail`, `OrderLowLevelStatus`, `OrderOrigin`, `OrderTransactionStatus`, `ResultType`, and `FailureType` enums.
* Additional enum values for `Labs` (`sonora_quest`, `crl`), `PayorCodeExternalProvider` (`apero`, `pverify`), and `Providers` (`tandem_source`, `samsung_health`).
* Several breaking changes have been introduced in this release:
* **`UserInfo.Address` and `UserInfoCreateRequest.Address`** now use the new `*UserAddress` type instead of `*Address`. Update any code that assigns or reads the `Address` field on these structs.
* **`UserRefreshSuccessResponse`**: The exported `Success bool` field, `GetSuccess()`, and `SetSuccess()` methods have been removed. Use the new `Success() bool` value-receiver method instead.
* **`BookPscAppointment`** now accepts `*LabTestsBookPscAppointmentRequest` instead of `*AppointmentBookingRequest`.
* New capabilities include three new sub-clients on the root `Client` — `Compendium`, `LabAccount`, and `OrderTransaction` — as well as new `DeliveryMode`, `DeliveryForm`, and `BolusPurpose` fields on `ClientFacingInsulinInjectionSample`, a new `ClientFacingDeviceSourceTypeInsulinPump` constant, and support for uploading multiple files in `ParserCreateJob`.
* The SDK now includes types for lab compendium search and cross-lab provider ID conversion. New types include `SearchCompendiumBody`, `ConvertCompendiumBody`, `SearchCompendiumResponse`, `ConvertCompendiumResponse`, `CanonicalCandidate`, `PerLabCandidate`, `RelatedCandidate`, `ProviderIdConversionResponse`, `CompendiumSearchLabs`, and `SearchMode`.
* The SDK now includes two new client packages: `compendium` (with `Search` and `Convert` methods) and `labaccount` (with `GetTeamLabAccounts`), enabling lab compendium search/conversion and team lab account management. New types `ClientFacingLabAccount`, `GetTeamLabAccountsResponse`, `LabAccountDelegatedFlow`, `LabAccountStatus`, and `UsState` are available in the root package. The `insulin_pump` source type constant has been added to the electrocardiogram and menstrual cycle source type enums.
* The SDK now includes a new `ordertransaction` package with a `Client` that exposes three methods: `GetTransaction`, `GetTransactionResult`, and `GetTransactionResultPdf` for interacting with order transaction endpoints. New types `GetOrderTransactionResponse` and `OrderSummary` have been added, along with a new `Bytes` pointer helper and a new `ClientFacingSleepCycleSourceTypeInsulinPump` source type constant.
