## v2.0.0 - 2026-04-13
* The `GetWheelchairUse()` accessor method has been removed from both `ClientFacingActivity` and `ClientFacingProfile`. Callers should access the `WheelchairUse` field directly on the respective struct instead.
* Three new expression types are now available for health data queries: `DerivedReadinessColumnExpr` (with readiness columns such as `recovery_score`, `strain_score`, `stress_score`, etc.), `AwakeningsValueMacroExpr`, and `InsulinInjectionTimeseriesExpr`. The `IndexColumnExprIndexDerivedReadiness` and `SleepColumnExprSleepRecoveryReadinessScore` constants have also been added.
**Breaking changes:** The `AggregateExprArgVisitor`, `QueryGroupByItemVisitor`, and `QuerySelectItemVisitor` interfaces each have three new required methods (`VisitDerivedReadinessColumnExpr`, `VisitAwakeningsValueMacroExpr`, `VisitInsulinInjectionTimeseriesExpr`); all existing implementations must add these methods. The `Placeholder` struct no longer exposes `GetPlaceholder()` or `SetPlaceholder()` — use the new `Placeholder()` method instead. `QueryBatch.Timeframe` and `QueryBatch.Queries` are now always serialized (no longer omitted when empty). The `IntervalTimeseriesExprTimeseriesInsulinInjection` constant has been removed; use `InsulinInjectionTimeseriesExpr` instead.
* **Breaking changes** to `ParsingJob` and `ResultMetadata` types in the lab report API.
* **`ParsingJob`**: The `JobId` field and its `GetJobId()`/`SetJobId()` methods have been removed. A new optional `FailureReason` field (`*ParsingJobFailureReason`) has been added along with a `ParsingJobFailureReason` enum (`invalid_input`, `low_quality`, `not_english`).
* **`ResultMetadata`**: The fields `PatientFirstName`, `PatientLastName`, `Dob`, and `LabName` have changed from required `string` values to optional `*string` pointers — callers must dereference these values and update setter call sites. A new optional `Gender` field (`*ResultMetadataGender`) has been added with a corresponding `ResultMetadataGender` enum (`male`, `female`, `other`).
* **`BodyCreateLabReportParserJob`**: The `File` field has changed from `io.Reader` to `[]io.Reader` to support multiple file uploads.
* The SDK now includes significant expansions to the lab tests API. New appointment booking options have been added: `AppointmentBookingRequest` and `AppointmentRescheduleRequest` now support `AppointmentNotes`, `AsyncConfirmation`, and confirmation timeout fields. New filter parameters have been added to `LabTestsGetMarkersRequest` (`LabSlug`), `LabTestsGetOrdersRequest` (`OrderTransactionId`), and `LabTestsGetPscAppointmentAvailabilityRequest` (`AllowStale`). A new `LabTestsBookPscAppointmentRequest` struct supports idempotency key for PSC appointment booking. The `SonoraQuest` provider and lab have been added as enum values. Several previously exported types (`BiomarkerResult`, `ClinicalInformation`, `LabResultsMetadata`, `LabResultsRaw`, `SampleData`, `OrderLowLevelStatus`, `FailureType`, `ResultType`, `ParentBiomarkerData`, `MissingBiomarkerResult`, `UtcTimestampWithTimezoneOffset`) have been removed — consumers referencing these types will need to update their code.
* Several breaking changes have been made to bulk operation request types. The `TeamId` field and `SetTeamId` method have been removed from `BulkExportConnectionsBody`, `BulkImportConnectionsBody`, `BulkPauseConnectionsBody`, `BulkTriggerHistoricalPullBody`, and `LinkListBulkOpsRequest` — team identity is now inferred from context, so any code referencing these fields must be updated. The exported types `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` have also been removed.
* New enum values `ManualProvidersSamsungHealth` and `PasswordProvidersTandemSource` are now available. `ClientFacingSleep` gains a `RecoveryReadinessScore` field, and `ManualConnectionData` gains `VitalIosSdkVersion`, `VitalAndroidSdkVersion`, and `GrantedPermissions` fields.
* Several breaking changes have been introduced alongside new capabilities:
**Breaking changes:**
* `UserRefreshErrorResponse.Success` is no longer an exported struct field; it is now a literal-enforced `false` value accessible only via the new `Success()` method. Code reading `.Success` directly will no longer compile.
* `HistoricalPullCompleted.IsFinal` is no longer an exported struct field; it is now a literal-enforced `true` value accessible only via the new `IsFinal()` method. Code reading `.IsFinal` directly will no longer compile.
**New capabilities:**
* `Address`, `PatientAddressCompatible`, and `PatientAddressWithValidation` now include an optional `AccessNotes` field.
* `ClientFacingOrder` now exposes `ClinicalNotes`, `LastEvent`, `Origin`, and `OrderTransaction` fields.
* `ClientFacingOrderEvent` now includes an optional `StatusDetail` field.
* New types `BiomarkerResult`, `MissingBiomarkerResult`, `ParentBiomarkerData`, `LabResultsRaw`, `SampleData`, `PerformingLaboratory`, `ClinicalInformation`, and `UtcTimestampWithTimezoneOffset` are available for structured lab result handling.
* New webhook event types `ClientFacingLabReportParsingJobCreatedEvent` and `ClientFacingLabReportParsingJobUpdatedEvent` are now available.
* New enums: `OrderLowLevelStatus`, `OrderOrigin`, `OrderStatusDetail`, `OrderTransactionStatus`.
* New order transaction types: `ClientFacingOrderTransaction`, `ClientFacingOrderInTransaction`.
* Several breaking changes have been introduced in this release:
* The `Address` field on `UserInfo` and `UserInfoCreateRequest` (and their associated `GetAddress`/`SetAddress` methods) now use the new `*UserAddress` type instead of `*Address`. Update call sites to use `UserAddress` wherever `Address` was previously used.
* `UserRefreshSuccessResponse.GetSuccess()` and `SetSuccess()` have been removed; the `success` field is now enforced as a JSON literal. Use the new `Success() bool` method to read the value.
* The `BookPscAppointment` method on `LabTestsClient` now accepts `*LabTestsBookPscAppointmentRequest` instead of `*AppointmentBookingRequest`; update call sites accordingly.
* New capabilities include three additional top-level sub-clients (`Compendium`, `LabAccount`, `OrderTransaction`), new `DeliveryMode`, `DeliveryForm`, and `BolusPurpose` fields on `ClientFacingInsulinInjectionSample`, a new `ClientFacingDeviceSourceTypeInsulinPump` constant, and support for multiple file uploads in the lab report parser.
* The SDK now includes types for the lab test compendium search and conversion APIs. New request types `SearchCompendiumBody` and `ConvertCompendiumBody`, response types `SearchCompendiumResponse` and `ConvertCompendiumResponse`, and supporting types (`CanonicalCandidate`, `PerLabCandidate`, `RelatedCandidate`, `ProviderIdConversionResponse`) are available, along with the `CompendiumSearchLabs` and `SearchMode` enums.
* The SDK now includes two new client packages: `compendium` (with `Search` and `Convert` methods) and `labaccount` (with `GetTeamLabAccounts`). New types `ClientFacingLabAccount`, `GetTeamLabAccountsResponse`, `LabAccountStatus`, `LabAccountDelegatedFlow`, and `UsState` are available in the top-level package. The `insulin_pump` source type has also been added to the ECG and menstrual cycle source type enums.
* The SDK now includes a new `ordertransaction` package with a `Client` exposing `GetTransaction`, `GetTransactionResult`, and `GetTransactionResultPdf` methods for the `/v3/order_transaction` endpoints. Two new types, `GetOrderTransactionResponse` and `OrderSummary`, are available in the root package. A new `insulin_pump` source type constant (`ClientFacingSleepCycleSourceTypeInsulinPump`) and a `Bytes` pointer helper have also been added.
