## v2.0.0 - 2026-04-03
* The `GetWheelchairUse()` accessor method has been removed from both `ClientFacingActivity` and `ClientFacingProfile`. Callers that relied on these methods must now access the `WheelchairUse` field directly (e.g., `activity.WheelchairUse` or `profile.WheelchairUse`).
* The SDK now supports three new query expression types: `DerivedReadinessColumnExpr` for querying derived readiness columns (sleep score, recovery score, recovery zone, stress score, strain score, etc.), `AwakeningsValueMacroExpr` for the "awakenings" value macro, and `InsulinInjectionTimeseriesExpr` for insulin injection timeseries data. These new types are available as variants in `AggregateExprArg`, `QueryGroupByItem`, and `QuerySelectItem` union types, with corresponding visitor methods. Note: `IntervalTimeseriesExprTimeseriesInsulinInjection` has been removed — use `InsulinInjectionTimeseriesExpr` instead. Additionally, `Placeholder.GetPlaceholder()` and `SetPlaceholder()` have been replaced with a `Placeholder()` method that reflects its new literal-field semantics.
* **Breaking changes to `ParsingJob` and `ResultMetadata` types:**
* `ParsingJob.JobId` (and its `GetJobId()`/`SetJobId()` methods) has been removed. Callers referencing this field must remove those references.
* `BodyCreateLabReportParserJob.File` changed from `io.Reader` to `[]io.Reader`; update call sites to pass a slice of readers.
* `ResultMetadata` fields `PatientFirstName`, `PatientLastName`, `Dob`, and `LabName` are now `*string` (optional pointers) instead of `string`; callers must dereference the returned pointer. The corresponding `Get*` and `Set*` methods have updated signatures accordingly.
**New additions:**
* `ParsingJob` now exposes a `FailureReason *ParsingJobFailureReason` field with the new `ParsingJobFailureReason` enum (`invalid_input`, `low_quality`, `not_english`).
* `ResultMetadata` now includes a `Gender *ResultMetadataGender` field with the new `ResultMetadataGender` enum (`male`, `female`, `other`).
* Several breaking changes have been made to bulk operation request types. The `TeamId` field and `SetTeamId()` method have been removed from `BulkExportConnectionsBody`, `BulkImportConnectionsBody`, `BulkPauseConnectionsBody`, `BulkTriggerHistoricalPullBody`, and `LinkListBulkOpsRequest`. The exported types `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` have also been removed — update any code referencing these fields or types.
* New provider constants `ManualProvidersSamsungHealth` and `PasswordProvidersTandemSource` are now available. `ClientFacingSleep` gains a new `RecoveryReadinessScore` field, and `ManualConnectionData` gains `VitalIosSdkVersion`, `VitalAndroidSdkVersion`, and `GrantedPermissions` fields.
* The SDK now includes several new capabilities for order management and lab results:
* `ClientFacingOrder` gains `ClinicalNotes`, `LastEvent`, `Origin`, and `OrderTransaction` fields; new supporting types `ClientFacingOrderTransaction`, `ClientFacingOrderInTransaction`, `OrderOrigin`, `OrderLowLevelStatus`, `OrderTransactionStatus`, and `OrderStatusDetail` are available.
* `ClientFacingOrderEvent` now exposes an optional `StatusDetail` field.
* New webhook event types `ClientFacingLabReportParsingJobCreatedEvent` and `ClientFacingLabReportParsingJobUpdatedEvent` are available for lab report parsing job lifecycle events.
* New types for structured lab results: `BiomarkerResult`, `MissingBiomarkerResult`, `ParentBiomarkerData`, `LabResultsRaw`, `LabResultsMetadata`, `SampleData`, `PerformingLaboratory`, `ClinicalInformation`, and `UtcTimestampWithTimezoneOffset`.
* `Address`, `PatientAddressCompatible`, and `PatientAddressWithValidation` gain an optional `AccessNotes` field.
* `SonoraQuest` and `Crl` added to the `Labs` enum.
* Several breaking changes are included in this release.
* **`UserInfo.Address` and `UserInfoCreateRequest.Address`** now use the new `*UserAddress` type instead of `*Address`. Callers that pass or receive an `*Address` value for these fields must migrate to `*UserAddress`.
* **`BookPscAppointment`** (on both `labtests.Client` and `labtests.RawClient`) now accepts `*LabTestsBookPscAppointmentRequest` instead of `*AppointmentBookingRequest`. Update call sites to use the new request type.
* **`UserRefreshSuccessResponse.Success`** is no longer an exported struct field. It is now validated as a literal during JSON unmarshalling and exposed via a `Success() bool` method. Code that references `.Success` as a field (e.g. for assignment or struct initialization) must be updated to use the method instead.
* New capabilities also included: three new top-level clients (`Compendium`, `LabAccount`, `OrderTransaction`), richer insulin injection sample data (`DeliveryMode`, `DeliveryForm`, `BolusPurpose`), a new `insulin_pump` device source type, multi-file support in `ParserCreateJob`, and idempotency header support in `BookPscAppointment`.
* The SDK now includes types for lab test compendium search and conversion. New types include `SearchCompendiumBody`, `ConvertCompendiumBody`, `SearchCompendiumResponse`, `ConvertCompendiumResponse`, `CanonicalCandidate`, `PerLabCandidate`, `RelatedCandidate`, `ProviderIdConversionResponse`, `CompendiumSearchLabs`, and `SearchMode`.
* The SDK now includes two new API client packages: `compendium` (with `Search` and `Convert` methods) and `labaccount` (with `GetTeamLabAccounts`). New types `ClientFacingLabAccount`, `GetTeamLabAccountsResponse`, `LabAccountDelegatedFlow`, `LabAccountStatus`, and `UsState` are available in the root package. The `insulin_pump` source type has also been added to the ECG and menstrual cycle source type enums.
* The SDK now includes an `ordertransaction` package with a new `Client` that exposes `GetTransaction`, `GetTransactionResult`, and `GetTransactionResultPdf` methods for the `/v3/order_transaction` endpoints. Two new types, `GetOrderTransactionResponse` and `OrderSummary`, are available to work with the responses. Additionally, a new `insulin_pump` value has been added to the `ClientFacingSleepCycleSourceType` enum.
