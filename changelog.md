## v2.0.0 - 2026-04-13
* The `GetWheelchairUse()` accessor method has been removed from both `ClientFacingActivity` and `ClientFacingProfile`. Existing callers of these methods must update their code — access the `WheelchairUse` field directly (e.g., `obj.WheelchairUse`) as a replacement.
* The SDK now supports querying derived readiness, awakenings, and insulin injection data through the query expression API. New types `DerivedReadinessColumnExpr`, `AwakeningsValueMacroExpr`, and `InsulinInjectionTimeseriesExpr` have been added and are available as variants of `AggregateExprArg`, `QueryGroupByItem`, and `QuerySelectItem`. Visitor interface implementations for these three union types must now implement the three new `Visit*` methods (`VisitDerivedReadinessColumnExpr`, `VisitAwakeningsValueMacroExpr`, `VisitInsulinInjectionTimeseriesExpr`). Additionally, `Placeholder.GetPlaceholder()` and `Placeholder.SetPlaceholder()` have been removed — use the `Placeholder.Placeholder()` accessor instead, and note that `QueryBatch.Timeframe` and `QueryBatch.Queries` are now always serialized in JSON (no longer omitted when empty).
* Several breaking changes have been made to `ParsingJob` and `ResultMetadata`:
* **`ParsingJob.JobId` removed**: The `JobId` field and its `GetJobId()`/`SetJobId()` methods have been removed from `ParsingJob`. Remove any references to this field in your code.
* **`BodyCreateLabReportParserJob.File` is now `[]io.Reader`**: The `File` field changed from a single `io.Reader` to a slice (`[]io.Reader`). Update call sites to wrap single readers in a slice.
* **`ResultMetadata` fields are now `*string`**: `PatientFirstName`, `PatientLastName`, `Dob`, and `LabName` changed from `string` to `*string`. All getters and setters for these fields now use pointer types — add nil-checks or dereference as needed.
* New additions: the `ParsingJobFailureReason` enum (with values `invalid_input`, `low_quality`, `not_english`) is now available on `ParsingJob.FailureReason`, and the `ResultMetadataGender` enum (with values `male`, `female`, `other`) is now available on `ResultMetadata.Gender`.
* The SDK now supports Sonora Quest as a lab and appointment provider (`AppointmentProviderSonoraQuest`, `ClientFacingLabsSonoraQuest`). New fields have been added across multiple request and response types, including appointment notes, async booking confirmation with timeout controls, PSC idempotency keys, order transaction ID filtering, lab slug filtering for markers, `AllowStale` for PSC availability, `ClinicalNotes` for orders, and `AccessNotes` for addresses. Several types previously exported in the lab tests module — including `BiomarkerResult`, `MissingBiomarkerResult`, `FailureType`, `ClinicalInformation`, `SampleData`, `LabResultsMetadata`, `LabResultsRaw`, `ParentBiomarkerData`, `UtcTimestampWithTimezoneOffset`, `OrderLowLevelStatus`, and `ResultType` — have been removed; consumers referencing these types will need to update their code.
* Several breaking changes have been made to bulk operation request types. The `TeamId` field and `SetTeamId` method have been removed from `BulkExportConnectionsBody`, `BulkImportConnectionsBody`, `BulkPauseConnectionsBody`, `BulkTriggerHistoricalPullBody`, and `LinkListBulkOpsRequest`. The exported types `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` (along with their constructor functions) have been removed entirely — callers referencing these symbols must update their code. New additions include `ManualProvidersSamsungHealth` and `PasswordProvidersTandemSource` enum constants, a `RecoveryReadinessScore` field on `ClientFacingSleep`, and `VitalIosSdkVersion`, `VitalAndroidSdkVersion`, and `GrantedPermissions` fields on `ManualConnectionData`.
* Several breaking and additive changes have been made to the SDK's type system.
**Breaking changes:**
* `UserRefreshErrorResponse.Success` is no longer a directly accessible exported field. It is now a literal-validated boolean exposed via the `Success()` method. Update any code that reads `response.Success` directly.
* `HistoricalPullCompleted.IsFinal` is now a literal-validated private field exposed via the `IsFinal()` method instead of a public struct field.
**New capabilities:**
* New `BiomarkerResult`, `MissingBiomarkerResult`, `ParentBiomarkerData`, `PerformingLaboratory`, `ClinicalInformation`, `LabResultsRaw`, `LabResultsMetadata`, and `SampleData` types for richer lab result handling.
* New `ClientFacingLabReportParsingJobCreatedEvent` and `ClientFacingLabReportParsingJobUpdatedEvent` webhook event types for lab report parsing jobs.
* New `ClientFacingOrderTransaction` and `ClientFacingOrderInTransaction` types exposing order transaction info.
* `Address`, `PatientAddressCompatible`, and `PatientAddressWithValidation` now include an `AccessNotes` optional field.
* `ClientFacingOrder` gains `ClinicalNotes`, `LastEvent`, `Origin`, and `OrderTransaction` fields.
* `ClientFacingOrderEvent` gains a `StatusDetail` field.
* New `OrderStatusDetail`, `OrderLowLevelStatus`, `OrderOrigin`, and `OrderTransactionStatus` enumerations.
* Several breaking changes are included in this release:
* `UserInfo.Address` and `UserInfoCreateRequest.Address` now use `*UserAddress` instead of `*Address`. Callers must update all references from `*Address` to `*UserAddress`.
* `UserRefreshSuccessResponse.GetSuccess()` and `SetSuccess()` have been removed. The `success` field is now a validated literal handled internally during JSON marshal/unmarshal.
* `BookPscAppointment` now accepts `*LabTestsBookPscAppointmentRequest` instead of `*AppointmentBookingRequest`.
* `ParserCreateJob` now expects a slice of files instead of a single file.
* New additions include three new sub-clients (`Compendium`, `LabAccount`, `OrderTransaction`) on the top-level client, a new `UserAddress` type, new insulin delivery metadata fields (`DeliveryMode`, `DeliveryForm`, `BolusPurpose`) on `ClientFacingInsulinInjectionSample`, and the new `ClientFacingDeviceSourceTypeInsulinPump` constant.
* The SDK now includes types for the lab test compendium search and conversion APIs. New types include `SearchCompendiumBody`, `ConvertCompendiumBody`, `SearchCompendiumResponse`, `ConvertCompendiumResponse`, `CanonicalCandidate`, `PerLabCandidate`, `RelatedCandidate`, `ProviderIdConversionResponse`, and the `CompendiumSearchLabs` and `SearchMode` enums.
* The SDK now includes two new API client packages: `compendium` (with `Search` and `Convert` methods) and `labaccount` (with a `GetTeamLabAccounts` method). New supporting types have been added including `ClientFacingLabAccount`, `GetTeamLabAccountsResponse`, `LabAccountStatus`, `LabAccountDelegatedFlow`, and `UsState`. Existing source-type enums for ECG and menstrual cycle now include the `insulin_pump` value.
* The SDK now includes a new `ordertransaction` package with a `Client` that exposes `GetTransaction`, `GetTransactionResult`, and `GetTransactionResultPdf` methods for retrieving order transaction data and associated lab results. New model types `GetOrderTransactionResponse` and `OrderSummary` have also been added, along with a new `insulin_pump` source type constant and a `Bytes()` pointer utility helper.
