## v2.0.0 - 2026-04-08
* The `GetWheelchairUse()` accessor method has been removed from both `ClientFacingActivity` and `ClientFacingProfile`. Callers using these methods must migrate to direct struct field access (e.g., `obj.WheelchairUse`) with appropriate nil checks.
* The SDK now supports three new query expression types: `DerivedReadinessColumnExpr` (for querying derived readiness columns such as recovery score, strain score, and chronotype), `AwakeningsValueMacroExpr` (for awakenings value macro expressions), and `InsulinInjectionTimeseriesExpr` (a dedicated type for insulin injection timeseries, previously represented as an `IntervalTimeseriesExpr` variant).
* The `AggregateExprArgVisitor`, `QueryGroupByItemVisitor`, and `QuerySelectItemVisitor` interfaces have each gained three new required methods: `VisitDerivedReadinessColumnExpr`, `VisitAwakeningsValueMacroExpr`, and `VisitInsulinInjectionTimeseriesExpr`. Any existing implementations of these visitor interfaces must be updated to include these new methods.
* **Breaking changes to `ParsingJob` and `ResultMetadata` types:**
* `ParsingJob.JobId` (along with `GetJobId()` and `SetJobId()`) has been removed. Callers should remove references to this field.
* `BodyCreateLabReportParserJob.File` has changed from `io.Reader` to `[]io.Reader` to support multiple files; update call sites accordingly.
* `ResultMetadata` fields `PatientFirstName`, `PatientLastName`, `Dob`, and `LabName` have changed from `string` to `*string`; callers must dereference these values and update setter calls to pass `*string`.
* A new `FailureReason *ParsingJobFailureReason` field (with the `ParsingJobFailureReason` enum) has been added to `ParsingJob`.
* A new `Gender *ResultMetadataGender` field (with the `ResultMetadataGender` enum) has been added to `ResultMetadata`.
* The SDK now supports Sonora Quest as a lab provider (`AppointmentProviderSonoraQuest`, `ClientFacingLabsSonoraQuest`). New optional fields have been added to appointment booking (`AppointmentNotes`, `AsyncConfirmation`, sync/async timeout controls), order creation (`ClinicalNotes`), lab test creation (`LabAccountId`, `LabSlug`), order querying (`OrderTransactionId`), marker querying (`LabSlug`), PSC availability (`AllowStale`), and address types (`AccessNotes`). A new `LabTestsBookPscAppointmentRequest` type with idempotency key support has been introduced. Note: several previously exported types (`BiomarkerResult`, `ClinicalInformation`, `LabResultsMetadata`, `LabResultsRaw`, `MissingBiomarkerResult`, `ParentBiomarkerData`, `SampleData`, `UtcTimestampWithTimezoneOffset`, `FailureType`, `OrderLowLevelStatus`, `ResultType`) have been removed from this package.
* Several breaking changes have been made to bulk operation request types. The `TeamId` field and `SetTeamId` method have been removed from `BulkExportConnectionsBody`, `BulkImportConnectionsBody`, `BulkPauseConnectionsBody`, `BulkTriggerHistoricalPullBody`, and `LinkListBulkOpsRequest`. The exported types `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` have also been removed. Callers referencing these fields or types must remove those references. New additions include the `ManualProvidersSamsungHealth` and `PasswordProvidersTandemSource` provider constants, a `RecoveryReadinessScore` field on `ClientFacingSleep`, and new `VitalIosSdkVersion`, `VitalAndroidSdkVersion`, and `GrantedPermissions` fields on `ManualConnectionData`.
* The SDK now supports lab report parsing job webhook events (`ClientFacingLabReportParsingJobCreatedEvent` and `ClientFacingLabReportParsingJobUpdatedEvent`), order transaction tracking via `ClientFacingOrderTransaction` and related types, and structured biomarker result payloads through `BiomarkerResult`, `MissingBiomarkerResult`, and `LabResultsRaw`. New fields have been added to `ClientFacingOrder` (`last_event`, `clinical_notes`, `origin`, `order_transaction`), `ClientFacingOrderEvent` (`status_detail`), and address types (`access_notes`). Additionally, `OrderLowLevelStatus`, `OrderOrigin`, `OrderStatusDetail`, and `OrderTransactionStatus` enumerations are now available.
* Several breaking changes have been introduced in this release:
* **`UserInfo.Address` and `UserInfoCreateRequest.Address`** now use the new `*UserAddress` type instead of `*Address`. Callers must update usages accordingly.
* **`BookPscAppointment`** now accepts `*LabTestsBookPscAppointmentRequest` instead of `*AppointmentBookingRequest`. Update call sites to use the new request type, which adds optional `IdempotencyKey` and `IdempotencyError` header fields.
* **`UserRefreshSuccessResponse`**: The exported `Success` field and `GetSuccess()`/`SetSuccess()` methods have been removed. The `success` value is now treated as a literal and exposed via an unexported-field accessor `Success() bool`.
* **`labreport.ParserCreateJob`** now accepts a slice of files instead of a single file, enabling multi-file upload in a single call.
* New additions include `Compendium`, `LabAccount`, and `OrderTransaction` sub-clients on the top-level `Client`, new `DeliveryMode`, `DeliveryForm`, and `BolusPurpose` fields on `ClientFacingInsulinInjectionSample`, the new `ClientFacingDeviceSourceTypeInsulinPump` constant, and the new `UserAddress` struct.
* The SDK now includes support for lab compendium search and provider ID conversion. New types `SearchCompendiumBody`, `ConvertCompendiumBody`, `SearchCompendiumResponse`, and `ConvertCompendiumResponse` are available, along with supporting types such as `CanonicalCandidate`, `PerLabCandidate`, `RelatedCandidate`, and `ProviderIdConversionResponse`. New enums `CompendiumSearchLabs` and `SearchMode` are also included.
* The SDK now includes two new API clients:
* **Compendium**: `compendium.Client` exposes `Search` and `Convert` methods for querying and converting lab test compendium data.
* **Lab Account**: `labaccount.Client` exposes `GetTeamLabAccounts` for retrieving lab accounts associated with a team.
* New supporting types (`ClientFacingLabAccount`, `GetTeamLabAccountsResponse`, `LabAccountDelegatedFlow`, `LabAccountStatus`, `UsState`) and a new `insulin_pump` source type for ECG and menstrual cycle data are also available.
* The SDK now includes a new `ordertransaction` package with a `Client` that exposes `GetTransaction`, `GetTransactionResult`, and `GetTransactionResultPdf` methods for querying order transactions. New types `GetOrderTransactionResponse` and `OrderSummary` have been added to support these endpoints. A new `ClientFacingSleepCycleSourceTypeInsulinPump` source type constant is also available.
