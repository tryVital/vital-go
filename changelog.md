## v2.0.0 - 2026-04-02
* The `GetWheelchairUse()` accessor method has been removed from both `ClientFacingActivity` and `ClientFacingProfile`. Callers that used `activity.GetWheelchairUse()` or `profile.GetWheelchairUse()` should migrate to direct field access via `activity.WheelchairUse` and `profile.WheelchairUse` respectively.
* The SDK now supports three new health data expression types: `DerivedReadinessColumnExpr` (for readiness-related columns such as sleep score, recovery score, and strain zone), `AwakeningsValueMacroExpr` (for the `awakenings` value macro), and `InsulinInjectionTimeseriesExpr` (insulin injection data, previously represented as an `IntervalTimeseriesExpr` variant). A new `SleepColumnExprSleepRecoveryReadinessScore` enum constant is also available on `SleepColumnExprSleep`.
**Breaking changes:** All three visitor interfaces (`AggregateExprArgVisitor`, `QueryGroupByItemVisitor`, `QuerySelectItemVisitor`) require three new methods — `VisitDerivedReadinessColumnExpr`, `VisitAwakeningsValueMacroExpr`, and `VisitInsulinInjectionTimeseriesExpr` — which must be implemented by any existing visitor. The `IntervalTimeseriesExprTimeseriesInsulinInjection` constant has been removed. The `Placeholder` struct's exported `Placeholder bool` field, `GetPlaceholder()`, and `SetPlaceholder()` have been removed in favour of an unexported literal with a `Placeholder() bool` accessor. `QueryBatch.Timeframe` and `QueryBatch.Queries` JSON serialization no longer omits empty values.
* Several breaking changes have been made to lab report parsing types:
* **`ParsingJob`**: The `JobId` field and its `GetJobId`/`SetJobId` methods have been removed. A new `FailureReason` field (type `*ParsingJobFailureReason`) has been added along with a new `ParsingJobFailureReason` enum (`invalid_input`, `low_quality`, `not_english`).
* **`ResultMetadata`**: The `PatientFirstName`, `PatientLastName`, `Dob`, and `LabName` fields have changed from `string` to `*string`; all related getters and setters have updated signatures. A new `Gender` field (type `*ResultMetadataGender`) has been added with a new `ResultMetadataGender` enum (`male`, `female`, `other`).
* **`BodyCreateLabReportParserJob`**: The `File` field type has changed from `io.Reader` to `[]io.Reader` to support submitting multiple files per request.
* Callers must dereference pointer fields where previously plain strings were used, remove references to `JobId`/`GetJobId`/`SetJobId`, and update `File` assignments to use a slice.
* The SDK now includes expanded lab-testing capabilities. A new `LabTestsBookPscAppointmentRequest` type supports idempotency-key-aware PSC appointment booking. `AppointmentBookingRequest` and `AppointmentRescheduleRequest` gain optional `AppointmentNotes`, `AsyncConfirmation`, and confirmation-timeout fields. The Sonora Quest lab provider is now available via `AppointmentProviderSonoraQuest` and `ClientFacingLabsSonoraQuest`. `AppointmentPscLabs` has been promoted from an untyped string alias to a named type with typed constants (`AppointmentPscLabsQuest`, `AppointmentPscLabsSonoraQuest`); code that previously assigned arbitrary strings to this type will no longer compile. Additional new fields include `OrderTransactionId` on `ClientFacingAppointment` and order-list filters, `LabSlug` on `LabTestsGetMarkersRequest`, `AllowStale` on PSC availability requests, `ClinicalNotes` on `CreateOrderRequestCompatible`, `LabAccountId`/`LabSlug` on `CreateLabTestRequest`, `AccessNotes` on `PatientAddress` and `UsAddress`, and `AppointmentNotes` on `RequestAppointmentRequest`.
* Several breaking changes have been made to bulk operation request types. The `TeamId` field and `SetTeamId` method have been removed from `BulkExportConnectionsBody`, `BulkImportConnectionsBody`, `BulkPauseConnectionsBody`, `BulkTriggerHistoricalPullBody`, and `LinkListBulkOpsRequest`. The exported types `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` have also been removed. Callers using any of these symbols must remove those references.
* New additions include `ManualProvidersSamsungHealth` and `PasswordProvidersTandemSource` provider constants, a `RecoveryReadinessScore` field on `ClientFacingSleep`, and new `VitalIosSdkVersion`, `VitalAndroidSdkVersion`, and `GrantedPermissions` fields on `ManualConnectionData`.
* The SDK now supports new order lifecycle features and lab result parsing capabilities.
* New types `ClientFacingLabReportParsingJobCreatedEvent` and `ClientFacingLabReportParsingJobUpdatedEvent` enable handling of `lab_report.parsing_job.created` and `lab_report.parsing_job.updated` webhook events. Order tracking is enhanced with `ClientFacingOrderTransaction`, `ClientFacingOrderInTransaction`, and the new `LastEvent`, `ClinicalNotes`, `Origin`, and `OrderTransaction` fields on `ClientFacingOrder`. Structured lab result parsing is now available via `BiomarkerResult`, `MissingBiomarkerResult`, `LabResultsRaw`, `SampleData`, and related types. Address types now include an optional `AccessNotes` field.
* Several breaking changes are included in this release:
* **`UserInfo.Address` and `UserInfoCreateRequest.Address`** now have type `*UserAddress` instead of `*Address`. Update any code that passes or receives an `*Address` for these fields to use `*UserAddress`.
* **`UserRefreshSuccessResponse`**: The exported `GetSuccess() bool` method and `SetSuccess()` setter have been removed. The `success` field is now a private literal-validated value; use the new `Success() bool` method to read it.
* **`labtests.BookPscAppointment`**: The `request` parameter type has changed from `*AppointmentBookingRequest` to `*LabTestsBookPscAppointmentRequest`. Update call sites to construct the new type.
* **`labreport.ParserCreateJob`**: The `File` field now accepts a slice (`[]File`) instead of a single `File`. Update usages to pass a slice.
* New capabilities also added: `Compendium`, `LabAccount`, and `OrderTransaction` sub-clients on the root client; `DeliveryMode`, `DeliveryForm`, and `BolusPurpose` fields on `ClientFacingInsulinInjectionSample`; and a new `ClientFacingDeviceSourceTypeInsulinPump` constant.
* The SDK now includes types for lab compendium search and provider ID conversion. New types `SearchCompendiumBody`, `ConvertCompendiumBody`, `SearchCompendiumResponse`, and `ConvertCompendiumResponse` are available, along with supporting models (`CanonicalCandidate`, `PerLabCandidate`, `RelatedCandidate`, `ProviderIdConversionResponse`) and enums (`CompendiumSearchLabs`, `SearchMode`).
* The SDK now includes two new API client packages: `compendium` (with `Search` and `Convert` methods) and `labaccount` (with `GetTeamLabAccounts`), along with new supporting types such as `ClientFacingLabAccount`, `LabAccountStatus`, `LabAccountDelegatedFlow`, and `UsState`. New `insulin_pump` source type constants have also been added to the ECG and menstrual cycle source type enumerations.
* The SDK now includes a new `ordertransaction` package with a `Client` that supports fetching order transactions (`GetTransaction`), lab results (`GetTransactionResult`), and PDF lab result reports (`GetTransactionResultPdf`). Two new types, `GetOrderTransactionResponse` and `OrderSummary`, are also available. Additionally, a new `insulin_pump` source type (`ClientFacingSleepCycleSourceTypeInsulinPump`) has been added to the sleep cycle source type enum.
