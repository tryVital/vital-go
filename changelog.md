## v2.0.0 - 2026-04-09
* The `GetWheelchairUse()` accessor methods have been removed from `ClientFacingActivity` and `ClientFacingProfile`. Callers using these methods must migrate to direct field access (e.g., `activity.WheelchairUse` or `profile.WheelchairUse`) to avoid compile errors.
* The SDK now supports derived readiness, awakenings, and insulin injection expression types in query building. `DerivedReadinessColumnExpr`, `AwakeningsValueMacroExpr`, and `InsulinInjectionTimeseriesExpr` are available as new variants in `AggregateExprArg`, `QueryGroupByItem`, and `QuerySelectItem` unions.
**Breaking changes:** The `AggregateExprArgVisitor`, `QueryGroupByItemVisitor`, and `QuerySelectItemVisitor` interfaces each require three new methods (`VisitDerivedReadinessColumnExpr`, `VisitAwakeningsValueMacroExpr`, `VisitInsulinInjectionTimeseriesExpr`) — all existing implementations must add these methods. The `IntervalTimeseriesExprTimeseriesInsulinInjection` constant has been removed; use `InsulinInjectionTimeseriesExpr` instead. The `Placeholder` struct's `GetPlaceholder()` / `SetPlaceholder()` methods have been removed in favour of an unexported literal; callers that referenced these methods must update their code.
* **Breaking changes** to `ParsingJob` and `ResultMetadata` types:
* `ParsingJob.JobId` field and its `GetJobId()`/`SetJobId()` methods have been removed. A new `FailureReason *ParsingJobFailureReason` field (with getter/setter) is now available, along with a new `ParsingJobFailureReason` enum type (`invalid_input`, `low_quality`, `not_english`).
* `ResultMetadata` fields `PatientFirstName`, `PatientLastName`, `Dob`, and `LabName` have changed from `string` to `*string`; callers must update getter usage to dereference the pointer and update setter call sites to pass `*string`.
* A new `Gender *ResultMetadataGender` field has been added to `ResultMetadata`, along with a new `ResultMetadataGender` enum type (`male`, `female`, `other`).
* `BodyCreateLabReportParserJob.File` has changed from `io.Reader` to `[]io.Reader` to support multiple file uploads.
* The `TeamId` field and `SetTeamId` method have been removed from `BulkExportConnectionsBody`, `BulkImportConnectionsBody`, `BulkPauseConnectionsBody`, `BulkTriggerHistoricalPullBody`, and `LinkListBulkOpsRequest`. The associated types `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` have also been removed — callers referencing these symbols must update their code. New capabilities include a `RecoveryReadinessScore` field on `ClientFacingSleep`, new `VitalIosSdkVersion`, `VitalAndroidSdkVersion`, and `GrantedPermissions` fields on `ManualConnectionData`, and new provider enum values `ManualProvidersSamsungHealth` and `PasswordProvidersTandemSource`.
* The SDK adds several new capabilities for order management and lab results:
* New `AccessNotes` field on `Address`, `PatientAddressCompatible`, and `PatientAddressWithValidation` for delivery access instructions.
* New `BiomarkerResult`, `MissingBiomarkerResult`, `ParentBiomarkerData`, `LabResultsRaw`, and supporting types for structured lab biomarker data.
* New webhook event types `ClientFacingLabReportParsingJobCreatedEvent` and `ClientFacingLabReportParsingJobUpdatedEvent` for lab report parsing job lifecycle events.
* New `ClientFacingOrderTransaction` and `ClientFacingOrderInTransaction` types, plus new `LastEvent`, `ClinicalNotes`, `Origin`, and `OrderTransaction` fields on `ClientFacingOrder`.
* New `StatusDetail` field on `ClientFacingOrderEvent` and new `OrderStatusDetail`, `OrderLowLevelStatus`, `OrderOrigin`, and `OrderTransactionStatus` enums.
* Several breaking changes have been introduced in this release:
* **`UserInfo.Address` and `UserInfoCreateRequest.Address`** now use `*UserAddress` instead of `*Address`. Callers must update references and update `SetAddress` calls to pass `*UserAddress`.
* **`UserRefreshSuccessResponse`**: The `Success` JSON field is no longer a serializable struct field. `GetSuccess()` has been replaced with `Success() bool` (no pointer receiver, no setter). `SetSuccess()` has been removed.
* **`BookPscAppointment`**: The request parameter type has changed from `*AppointmentBookingRequest` to `*LabTestsBookPscAppointmentRequest`.
* **Bulk link operations** (`BulkImport`, `BulkTriggerHistoricalPull`, `BulkExport`, `BulkPause`): Requests are now sent as a JSON body instead of query parameters.
* New additions include `Compendium`, `LabAccount`, and `OrderTransaction` top-level clients; `UserAddress` struct; new `ClientFacingInsulinInjectionSample` delivery fields (`DeliveryMode`, `DeliveryForm`, `BolusPurpose`); the `insulin_pump` device source type constant; and form URL-encoded request body support.
* The SDK now includes types for the lab compendium search and conversion APIs. New types include `SearchCompendiumBody`, `ConvertCompendiumBody`, `SearchCompendiumResponse`, `ConvertCompendiumResponse`, `CanonicalCandidate`, `PerLabCandidate`, `RelatedCandidate`, `ProviderIdConversionResponse`, and the `CompendiumSearchLabs` and `SearchMode` enums.
* The SDK now includes two new API clients: `compendium` (with `Search` and `Convert` methods for lab compendium operations) and `labaccount` (with `GetTeamLabAccounts` for retrieving team lab accounts). New supporting types — `ClientFacingLabAccount`, `GetTeamLabAccountsResponse`, `LabAccountDelegatedFlow`, `LabAccountStatus`, and `UsState` — are available in the root package. Source-type enums for electrocardiogram and menstrual cycle data now include the `insulin_pump` value.
* The SDK now includes a new `ordertransaction` package with a `Client` that exposes `GetTransaction`, `GetTransactionResult`, and `GetTransactionResultPdf` methods for working with order transaction endpoints. New types `GetOrderTransactionResponse` and `OrderSummary` are available in the root package, and a new `insulin_pump` source type constant (`ClientFacingSleepCycleSourceTypeInsulinPump`) has been added.
