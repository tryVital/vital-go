## v2.0.0 - 2026-04-01
* The `GetWheelchairUse()` accessor method has been removed from both `ClientFacingActivity` and `ClientFacingProfile`. Existing code calling these methods will no longer compile. Replace any calls to `GetWheelchairUse()` with direct access to the `WheelchairUse` struct field.
* The SDK now supports querying derived readiness data, insulin injection timeseries, and awakening metrics through new expression types: `DerivedReadinessColumnExpr`, `InsulinInjectionTimeseriesExpr`, and `AwakeningsValueMacroExpr`. The `AggregateExprArgVisitor`, `QueryGroupByItemVisitor`, and `QuerySelectItemVisitor` interfaces have been extended with new visit methods for these types — existing implementations must add `VisitDerivedReadinessColumnExpr`, `VisitAwakeningsValueMacroExpr`, and `VisitInsulinInjectionTimeseriesExpr` to compile. Additionally, `insulin_injection` has been removed from `IntervalTimeseriesExprTimeseries` and is now represented by the dedicated `InsulinInjectionTimeseriesExpr` type.
* **Breaking changes to lab report parsing types:**
* `ParsingJob.JobId` field and its getter/setter (`GetJobId`, `SetJobId`) have been removed. A new `FailureReason` field (of type `*ParsingJobFailureReason`) and corresponding getter/setter have been added in their place.
* `BodyCreateLabReportParserJob.File` has changed from `io.Reader` to `[]io.Reader` to support submitting multiple files in a single job.
* Several `ResultMetadata` fields (`PatientFirstName`, `PatientLastName`, `Dob`, `LabName`) have changed from `string` to `*string`; their getters and setters have been updated accordingly. A new optional `Gender` field (of type `*ResultMetadataGender`) has also been added.
* New exported types `ParsingJobFailureReason` and `ResultMetadataGender` are now available with associated constants and constructor functions.
* The SDK now supports expanded lab testing capabilities including PSC appointment booking with idempotency keys, async confirmation options for appointment booking and rescheduling, and Sonora Quest as a new appointment provider and lab option. New optional fields have been added to orders (`ClinicalNotes`), addresses (`AccessNotes`), appointments (`AppointmentNotes`, `OrderTransactionId`), and lab test creation (`LabAccountId`, `LabSlug`). Note: Several types have been removed from the public API surface — `BiomarkerResult`, `ClinicalInformation`, `LabResultsMetadata`, `LabResultsRaw`, `MissingBiomarkerResult`, `OrderLowLevelStatus`, `ParentBiomarkerData`, `SampleData`, `UtcTimestampWithTimezoneOffset`, `FailureType`, `ResultType`, and their associated union/visitor types are no longer exported. Additionally, `AppointmentPscLabs` has changed from a type alias (`= string`) to a named string type, which may affect assignments in existing code.
* Several breaking changes have been made to bulk connection operation request structs. The `TeamId` field and `SetTeamId` method have been removed from `BulkExportConnectionsBody`, `BulkImportConnectionsBody`, `BulkPauseConnectionsBody`, `BulkTriggerHistoricalPullBody`, and `LinkListBulkOpsRequest`. The exported types `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` (along with their constructors and constants) have also been removed — callers referencing these symbols must remove those references. Additionally, `ClientFacingSleep` gains a new `RecoveryReadinessScore` field sourced from Oura, Whoop, and Ultrahuman; `ManualConnectionData` gains `VitalIosSdkVersion`, `VitalAndroidSdkVersion`, and `GrantedPermissions` fields; and new provider constants `ManualProvidersSamsungHealth` and `PasswordProvidersTandemSource` are now available.
* Several previously exported struct fields have been changed to private literals.
* `HistoricalPullCompleted.IsFinal` (`bool`) is no longer a settable public field; it is now a private literal always equal to `true`. Code that reads or sets `obj.IsFinal` will no longer compile. Use the new `obj.IsFinal()` accessor method instead.
* `UserRefreshErrorResponse.Success` (`bool`) is no longer a settable public field; it is now a private literal. Use the new `obj.Success()` accessor method instead.
* New capabilities also added in this release:
* New `BiomarkerResult`, `MissingBiomarkerResult`, `LabResultsRaw`, and `LabResultsMetadata` types for structured lab result data.
* New `ClientFacingLabReportParsingJobCreatedEvent` and `ClientFacingLabReportParsingJobUpdatedEvent` webhook event types.
* New `ClientFacingOrderTransaction` and related types for order transaction tracking; `ClientFacingOrder` gains `LastEvent`, `ClinicalNotes`, `Origin`, and `OrderTransaction` fields.
* New `AccessNotes` field on `Address`, `PatientAddressCompatible`, and `PatientAddressWithValidation`.
* New `StatusDetail` field on `ClientFacingOrderEvent` with the new `OrderStatusDetail` enum.
* New `OrderLowLevelStatus`, `OrderOrigin`, and `OrderTransactionStatus` enums.
* Several breaking changes are included in this release:
* `UserInfo.Address` and `UserInfoCreateRequest.Address` now use `*UserAddress` (a new dedicated type) instead of `*Address` — update any code that passes or receives an `*Address` in these fields to use `*UserAddress` instead.
* `UserRefreshSuccessResponse` no longer exposes a public `Success` field; it is replaced by a `Success() bool` method — update any direct field access (`resp.Success`) to a method call (`resp.Success()`). Additionally, `SetSuccess` has been removed.
* `BookPscAppointment` (on both `Client` and `RawClient` in the `labtests` package) now accepts `*LabTestsBookPscAppointmentRequest` instead of `*AppointmentBookingRequest` — update call sites to use the new request type, which also supports optional `IdempotencyKey` and `IdempotencyError` headers.
* New capabilities added: three new sub-clients (`Compendium`, `LabAccount`, `OrderTransaction`) are available on the top-level `Client`; `ClientFacingInsulinInjectionSample` gains `DeliveryMode`, `DeliveryForm`, and `BolusPurpose` fields; a new `ClientFacingDeviceSourceTypeInsulinPump` constant is available; and the `ParserCreateJob` endpoint now supports uploading multiple files.
* The SDK now includes types for the lab test compendium search and conversion API. New exported types include `SearchCompendiumBody`, `ConvertCompendiumBody`, `SearchCompendiumResponse`, `ConvertCompendiumResponse`, `CanonicalCandidate`, `PerLabCandidate`, `RelatedCandidate`, and `ProviderIdConversionResponse`, along with the `CompendiumSearchLabs` and `SearchMode` enums.
* The SDK now includes two new API client packages: `compendium` (with `Search` and `Convert` methods) and `labaccount` (with `GetTeamLabAccounts`). New types `ClientFacingLabAccount`, `GetTeamLabAccountsResponse`, `LabAccountDelegatedFlow`, `LabAccountStatus`, and `UsState` are also available. Additionally, `insulin_pump` has been added as a recognized source type for ECG and menstrual cycle data.
* The SDK now includes a new `ordertransaction` package with a `Client` that exposes `GetTransaction`, `GetTransactionResult`, and `GetTransactionResultPdf` methods for interacting with the `/v3/order_transaction` API. Two new types, `GetOrderTransactionResponse` and `OrderSummary`, are available in the root package to represent transaction data. A new `insulin_pump` value has also been added to the `ClientFacingSleepCycleSourceType` enum.
