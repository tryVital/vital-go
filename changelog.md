## v2.0.0 - 2026-04-07
* The `GetWheelchairUse()` accessor method has been removed from both `ClientFacingActivity` and `ClientFacingProfile`. Existing code calling these methods will no longer compile. To access the underlying field, read `WheelchairUse` directly from the struct (e.g., `activity.WheelchairUse`).
* Three new query expression types are now available: `DerivedReadinessColumnExpr`, `AwakeningsValueMacroExpr`, and `InsulinInjectionTimeseriesExpr`. These are supported in `AggregateExprArg`, `QueryGroupByItem`, and `QuerySelectItem` union types, along with their corresponding visitor interfaces.
**Breaking changes:** The `AggregateExprArgVisitor`, `QueryGroupByItemVisitor`, and `QuerySelectItemVisitor` interfaces each gain three new required methods (`VisitDerivedReadinessColumnExpr`, `VisitAwakeningsValueMacroExpr`, `VisitInsulinInjectionTimeseriesExpr`) — any existing implementations must add these methods. The `IntervalTimeseriesExprTimeseriesInsulinInjection` constant has been removed; use `InsulinInjectionTimeseriesExpr` instead. The `Placeholder` type no longer exposes `GetPlaceholder()` or `SetPlaceholder()` — the field is now treated as a fixed literal accessible via `Placeholder()`. The `QueryBatch.Timeframe` and `QueryBatch.Queries` fields are now always serialized (no longer omitted when empty).
* **Breaking changes to `ParsingJob` and `ResultMetadata`:**
* `ParsingJob.JobId` (and its `GetJobId`/`SetJobId` methods) has been removed. Use the new `FailureReason` field (`*ParsingJobFailureReason`) instead when accessing job failure information.
* `ResultMetadata` fields `PatientFirstName`, `PatientLastName`, `Dob`, and `LabName` changed from `string` to `*string`; callers must dereference these values and update setter calls accordingly.
* `BodyCreateLabReportParserJob.File` changed from `io.Reader` to `[]io.Reader`; callers must now pass a slice of readers.
* New `ParsingJobFailureReason` enum type added with values `invalid_input`, `low_quality`, and `not_english`.
* New `ResultMetadataGender` enum type added (`male`, `female`, `other`) with a corresponding `Gender` field on `ResultMetadata`.
* The SDK now supports additional lab appointment capabilities including async confirmation options (`AsyncConfirmation`, `SyncConfirmationTimeoutMillisecond`, `AsyncConfirmationTimeoutMillisecond`) on `AppointmentBookingRequest`, appointment notes across booking/rescheduling/appointment types, a new `LabTestsBookPscAppointmentRequest` type for PSC bookings with idempotency key support, and new `SonoraQuest` values for `AppointmentProvider` and `ClientFacingLabs` enums. Several previously exported types (`BiomarkerResult`, `ClinicalInformation`, `LabResultsMetadata`, `LabResultsRaw`, `MissingBiomarkerResult`, `OrderActivationType`, `OrderLowLevelStatus`, `ParentBiomarkerData`, `ResultType`, `SampleData`, `UtcTimestampWithTimezoneOffset`, and related union types) have been removed from the public API surface — callers referencing these types must update their code.
* Several breaking changes have been made to bulk operation request types. The `TeamId` field and `SetTeamId` method have been removed from `BulkExportConnectionsBody`, `BulkImportConnectionsBody`, `BulkPauseConnectionsBody`, `BulkTriggerHistoricalPullBody`, and `LinkListBulkOpsRequest`. The exported types `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` (and their constructors/constants) have also been removed. Callers that reference these fields or types must remove those usages.
* New additions include: `ManualProvidersSamsungHealth` and `PasswordProvidersTandemSource` provider enum constants; a `RecoveryReadinessScore` field on `ClientFacingSleep` sourced from Oura, Whoop, and Ultrahuman; and `VitalIosSdkVersion`, `VitalAndroidSdkVersion`, and `GrantedPermissions` fields on `ManualConnectionData`.
* The SDK now includes new types and fields for lab report parsing job events (`ClientFacingLabReportParsingJobCreatedEvent`, `ClientFacingLabReportParsingJobUpdatedEvent`), order transaction tracking (`ClientFacingOrderTransaction`, `ClientFacingOrderInTransaction`), and detailed biomarker results (`BiomarkerResult`, `MissingBiomarkerResult`, `LabResultsRaw`). New fields have been added to `ClientFacingOrder` (`ClinicalNotes`, `LastEvent`, `Origin`, `OrderTransaction`), `Address`/`PatientAddressCompatible`/`PatientAddressWithValidation` (`AccessNotes`), and `ClientFacingOrderEvent` (`StatusDetail`). Additionally, `HistoricalPullCompleted.IsFinal` and `UserRefreshErrorResponse.Success` are now enforced as literal values and exposed via accessor methods instead of public fields.
* Several breaking changes are included in this release:
* The `Address` field on `UserInfo` and `UserInfoCreateRequest` (and their corresponding `GetAddress()`/`SetAddress()` methods) now use the new `UserAddress` type instead of `Address`. Update any code that references `*Address` in these contexts to use `*UserAddress`.
* `UserRefreshSuccessResponse.Success` is no longer an exported struct field. Access it via the new `Success()` method instead; the `SetSuccess()` setter has been removed.
* `BookPscAppointment` on both `Client` and `RawClient` now accepts `*LabTestsBookPscAppointmentRequest` instead of `*AppointmentBookingRequest`.
* New additions include three new top-level sub-clients (`Compendium`, `LabAccount`, `OrderTransaction`), a new `ClientFacingDeviceSourceTypeInsulinPump` enum value, and new `DeliveryMode`, `DeliveryForm`, and `BolusPurpose` fields on `ClientFacingInsulinInjectionSample`. The lab report parser now accepts multiple files per job.
* The SDK now includes types for the lab compendium search and conversion APIs. New types `SearchCompendiumBody`, `ConvertCompendiumBody`, `SearchCompendiumResponse`, and `ConvertCompendiumResponse` are available, along with supporting types such as `CanonicalCandidate`, `PerLabCandidate`, `RelatedCandidate`, and `ProviderIdConversionResponse`. New enums `CompendiumSearchLabs` and `SearchMode` are also introduced.
* The SDK now includes two new API client packages: `compendium` (providing `Search` and `Convert` methods) and `labaccount` (providing `GetTeamLabAccounts`). New types `ClientFacingLabAccount`, `GetTeamLabAccountsResponse`, `LabAccountDelegatedFlow`, `LabAccountStatus`, and `UsState` are available in the root package. The `insulin_pump` source type is now recognized in ECG and menstrual cycle source type enums.
* The SDK now includes a new `ordertransaction` package with a `Client` that supports fetching order transaction details, lab results, and lab result PDFs via `GetTransaction`, `GetTransactionResult`, and `GetTransactionResultPdf`. Two new types, `GetOrderTransactionResponse` and `OrderSummary`, are also available in the root package. Additionally, a new `insulin_pump` source type constant has been added to `ClientFacingSleepCycleSourceType`.
