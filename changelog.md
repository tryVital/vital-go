## v2.0.0 - 2026-04-10
* The `GetWheelchairUse()` accessor method has been removed from both `ClientFacingActivity` and `ClientFacingProfile`. Callers using these methods should migrate to accessing the `WheelchairUse` field directly (e.g., `obj.WheelchairUse`).
* The `AggregateExprArgVisitor`, `QueryGroupByItemVisitor`, and `QuerySelectItemVisitor` interfaces now require three additional methods: `VisitDerivedReadinessColumnExpr`, `VisitAwakeningsValueMacroExpr`, and `VisitInsulinInjectionTimeseriesExpr`. Any existing implementation of these interfaces must add these methods or the code will fail to compile.
* Additionally, `Placeholder.Placeholder` (exported struct field) has been replaced by a private field accessible via the read-only `Placeholder()` method, and `GetPlaceholder()`/`SetPlaceholder()` have been removed. The `IntervalTimeseriesExprTimeseriesInsulinInjection` constant has been removed in favor of the new dedicated `InsulinInjectionTimeseriesExpr` type.
* New types `DerivedReadinessColumnExpr`, `AwakeningsValueMacroExpr`, and `InsulinInjectionTimeseriesExpr` are now available for use in aggregate, group-by, and select query expressions.
* **Breaking changes to lab report parsing types:**
* `ParsingJob.JobId` field and the associated `GetJobId()`/`SetJobId()` methods have been removed. Update any code referencing these symbols.
* `ResultMetadata` fields `PatientFirstName`, `PatientLastName`, `Dob`, and `LabName` are now optional pointer types (`*string`). All related getters and setters have been updated to use `*string`; callers must dereference these values.
* `BodyCreateLabReportParserJob.File` now accepts `[]io.Reader` (a slice) instead of a single `io.Reader`.
**New additions:**
* `ParsingJob` now exposes a `FailureReason` field of type `*ParsingJobFailureReason`, with constants `ParsingJobFailureReasonInvalidInput`, `ParsingJobFailureReasonLowQuality`, and `ParsingJobFailureReasonNotEnglish`.
* `ResultMetadata` now includes an optional `Gender` field of type `*ResultMetadataGender`, with constants `ResultMetadataGenderMale`, `ResultMetadataGenderFemale`, and `ResultMetadataGenderOther`.
* The SDK now includes expanded lab tests API support. New fields have been added to `AppointmentBookingRequest` (`AppointmentNotes`, `AsyncConfirmation`, `SyncConfirmationTimeoutMillisecond`, `AsyncConfirmationTimeoutMillisecond`), `AppointmentRescheduleRequest` (`AppointmentNotes`), `ClientFacingAppointment` (`OrderTransactionId`, `AppointmentNotes`), `CreateLabTestRequest` (`LabAccountId`, `LabSlug`), `CreateOrderRequestCompatible` (`ClinicalNotes`), `PatientAddress` and `UsAddress` (`AccessNotes`), and new filter fields on marker/order list requests. A new `LabTestsBookPscAppointmentRequest` type with idempotency key support has been introduced, along with `AppointmentProviderSonoraQuest` and `ClientFacingLabsSonoraQuest` enum values. Note: Several types have been removed from the public API surface including `BiomarkerResult`, `MissingBiomarkerResult`, `LabResultsMetadata`, `LabResultsRaw`, `ClinicalInformation`, `SampleData`, `ParentBiomarkerData`, `PerformingLaboratory`, `UtcTimestampWithTimezoneOffset`, `FailureType`, `ResultType`, `OrderLowLevelStatus`, and related union types.
* Several exported types and struct fields related to `TeamId` have been removed from the SDK. The `TeamId` field and `SetTeamId` method have been removed from `BulkExportConnectionsBody`, `BulkImportConnectionsBody`, `BulkPauseConnectionsBody`, `BulkTriggerHistoricalPullBody`, and `LinkListBulkOpsRequest`. The exported types `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` (including their constructors and constants) have also been removed. Callers using these fields or types must remove references to them. In addition, the SDK now supports `samsung_health` as a `ManualProviders` value, `tandem_source` as a `PasswordProviders` value, a new `RecoveryReadinessScore` field on `ClientFacingSleep`, and new `VitalIosSdkVersion`, `VitalAndroidSdkVersion`, and `GrantedPermissions` fields on `ManualConnectionData`.
* The SDK now exposes new types and fields for lab result modelling, lab report parsing job events (`ClientFacingLabReportParsingJobCreatedEvent`, `ClientFacingLabReportParsingJobUpdatedEvent`), order transaction tracking (`ClientFacingOrderTransaction`, `ClientFacingOrderInTransaction`), and richer order status semantics (`OrderStatusDetail`, `OrderLowLevelStatus`, `OrderOrigin`). `Address`, `PatientAddressCompatible`, and `PatientAddressWithValidation` now include an optional `AccessNotes` field. `ClientFacingOrder` gains `ClinicalNotes`, `LastEvent`, `Origin`, and `OrderTransaction` fields, and `ClientFacingOrderEvent` gains an optional `StatusDetail` field.
* Several breaking changes are included in this release.
* `UserInfo.Address` and `UserInfoCreateRequest.Address` fields now use the new `*UserAddress` type instead of `*Address`. Callers must update references accordingly.
* `UserRefreshSuccessResponse.Success` (exported field), `GetSuccess()`, and `SetSuccess()` have been removed; the `success` literal is now validated internally and exposed via a new `Success() bool` value-receiver method.
* `BookPscAppointment` now accepts `*LabTestsBookPscAppointmentRequest` instead of `*AppointmentBookingRequest`, enabling idempotency-key headers.
* `labreport.ParserCreateJob` now accepts a slice of files rather than a single file.
* New additions include three new top-level clients (`Compendium`, `LabAccount`, `OrderTransaction`), optional insulin delivery metadata fields (`DeliveryMode`, `DeliveryForm`, `BolusPurpose`) on `ClientFacingInsulinInjectionSample`, a new `ClientFacingDeviceSourceTypeInsulinPump` enum value, and internal support for form URL-encoded request bodies.
* The SDK now includes types for lab compendium search and provider ID conversion. New types include `SearchCompendiumBody`, `SearchCompendiumResponse`, `ConvertCompendiumBody`, `ConvertCompendiumResponse`, and supporting candidate types (`CanonicalCandidate`, `PerLabCandidate`, `RelatedCandidate`). New enums `CompendiumSearchLabs` and `SearchMode` are also available.
* The SDK now includes two new API client packages: `compendium` (with `Search` and `Convert` methods) and `labaccount` (with `GetTeamLabAccounts`). New types `ClientFacingLabAccount`, `GetTeamLabAccountsResponse`, `LabAccountDelegatedFlow`, `LabAccountStatus`, and `UsState` are available in the main package. The `insulin_pump` source type is now recognized in ECG and menstrual cycle source type enums.
* The SDK now includes a new `ordertransaction` package with a `Client` that exposes `GetTransaction`, `GetTransactionResult`, and `GetTransactionResultPdf` methods for working with order transactions. New types `GetOrderTransactionResponse` and `OrderSummary` have been added, along with a new `ClientFacingSleepCycleSourceTypeInsulinPump` source type constant and a `Bytes` pointer utility helper.
