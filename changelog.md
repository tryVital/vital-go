## v2.0.0 - 2026-04-01
* The `GetWheelchairUse()` getter method has been removed from both `ClientFacingActivity` and `ClientFacingProfile`. Callers that reference these methods must be updated; the `WheelchairUse` struct field can be accessed directly as a replacement.
* Three new query expression types are now available: `InsulinInjectionTimeseriesExpr` (replacing the former `IntervalTimeseriesExprTimeseriesInsulinInjection` constant), `DerivedReadinessColumnExpr` for readiness-related columns, and `AwakeningsValueMacroExpr` for the awakenings macro. The `SleepColumnExpr` enum gains a new `recovery_readiness_score` field. **Breaking:** The `AggregateExprArgVisitor`, `QueryGroupByItemVisitor`, and `QuerySelectItemVisitor` interfaces each have three new required `Visit*` methods; any consumer that implements these interfaces must add the new methods. Additionally, `IntervalTimeseriesExprTimeseriesInsulinInjection` has been removed from the `IntervalTimeseriesExprTimeseries` enum.
* **Breaking changes** to the lab report parsing types:
* `ParsingJob.JobId` field and its `GetJobId()`/`SetJobId()` methods have been removed. A new `FailureReason` field (`*ParsingJobFailureReason`) has been added along with a new `ParsingJobFailureReason` enum (`invalid_input`, `low_quality`, `not_english`).
* `ResultMetadata` fields `PatientFirstName`, `PatientLastName`, `Dob`, and `LabName` have changed type from `string` to `*string`; their getter and setter signatures have changed accordingly. A new `Gender` field (`*ResultMetadataGender`) has been added along with a new `ResultMetadataGender` enum (`male`, `female`, `other`).
* `BodyCreateLabReportParserJob.File` has changed from `io.Reader` to `[]io.Reader` to support multiple files.
* Callers must dereference pointer fields where previously a plain string was returned, update or remove usages of `JobId`, and update any code constructing `BodyCreateLabReportParserJob` to supply a slice of readers.
* Several exported types have been removed from the lab tests module, including `BiomarkerResult`, `MissingBiomarkerResult`, `LabResultsMetadata`, `LabResultsRaw`, `LabResultsRawResults`, `ClinicalInformation`, `SampleData`, `FailureType`, `ResultType`, `ParentBiomarkerData`, `UtcTimestampWithTimezoneOffset`, `OrderLowLevelStatus`, and others. Additionally, `AppointmentPscLabs` has changed from a type alias (`= string`) to a defined type, which is a breaking change for any code using it interchangeably with `string`.
* New capabilities include: Sonora Quest support (`AppointmentProviderSonoraQuest`, `ClientFacingLabsSonoraQuest`), async appointment booking confirmation options, appointment notes on booking/reschedule requests, a new `LabTestsBookPscAppointmentRequest` type with idempotency key support, additional filter fields (`LabSlug`, `OrderTransactionId`, `AllowStale`), and new optional fields on `CreateLabTestRequest`, `CreateOrderRequestCompatible`, `PatientAddress`, and `UsAddress`.
* Several breaking changes have been made to bulk operation request types. The `TeamId` field and `SetTeamId` method have been removed from `BulkExportConnectionsBody`, `BulkImportConnectionsBody`, `BulkPauseConnectionsBody`, `BulkTriggerHistoricalPullBody`, and `LinkListBulkOpsRequest`. The exported types `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` have also been removed. Callers referencing these fields, methods, or types must remove those references. New provider constants `ManualProvidersSamsungHealth` and `PasswordProvidersTandemSource` are now available, and `ClientFacingSleep` includes a new `RecoveryReadinessScore` field sourced from Oura, Whoop, and Ultrahuman.
* The SDK now includes support for lab report parsing job events (`ClientFacingLabReportParsingJobCreatedEvent`, `ClientFacingLabReportParsingJobUpdatedEvent`), order transactions (`ClientFacingOrderTransaction`, `ClientFacingOrderInTransaction`), and rich biomarker result types (`BiomarkerResult`, `MissingBiomarkerResult`, `LabResultsRaw`). New fields have been added to `ClientFacingOrder` (including `ClinicalNotes`, `LastEvent`, `Origin`, and `OrderTransaction`), `ClientFacingOrderEvent` (including `StatusDetail`), and `Address`/`PatientAddressCompatible` (including `AccessNotes`). New enums `OrderOrigin`, `OrderLowLevelStatus`, `OrderTransactionStatus`, and `OrderStatusDetail` are also available.
* The SDK introduces several breaking changes alongside new capabilities:
**Breaking changes:**
* `UserInfo.GetAddress()` / `SetAddress()` and `UserInfoCreateRequest.GetAddress()` / `SetAddress()` now use `*UserAddress` instead of `*Address`. Update call sites accordingly.
* `UserRefreshSuccessResponse.GetSuccess() bool` and the exported `Success` field have been removed. A new `Success() bool` method now validates this as a literal field during JSON deserialization; update any direct field accesses or `SetSuccess` calls.
* `BookPscAppointment` (on `LabTests` client) now accepts `*LabTestsBookPscAppointmentRequest` instead of `*AppointmentBookingRequest`.
* `ParserCreateJob` (on `LabReport` client) now accepts a slice of files instead of a single file.
**New features:**
* Three new top-level clients are available: `Compendium`, `LabAccount`, and `OrderTransaction`.
* New `ClientFacingDeviceSourceTypeInsulinPump` device source constant.
* `ClientFacingInsulinInjectionSample` now includes optional `DeliveryMode`, `DeliveryForm`, and `BolusPurpose` fields with corresponding new enum types.
* New `UserAddress` struct with full getter/setter support.
* The SDK now includes types for the lab compendium search and conversion APIs. New request types (`SearchCompendiumBody`, `ConvertCompendiumBody`) and response types (`SearchCompendiumResponse`, `ConvertCompendiumResponse`, `CanonicalCandidate`, `PerLabCandidate`, `RelatedCandidate`, `ProviderIdConversionResponse`) are available, along with new enums `CompendiumSearchLabs` and `SearchMode`.
* The SDK now includes two new API client packages: `compendium` (with `Search` and `Convert` methods) and `labaccount` (with `GetTeamLabAccounts`). New types `ClientFacingLabAccount`, `GetTeamLabAccountsResponse`, `LabAccountStatus`, `LabAccountDelegatedFlow`, and `UsState` are also available. Source type enums for electrocardiogram and menstrual cycle now include the `insulin_pump` value.
* The SDK now includes a new `ordertransaction` package with a `Client` that exposes `GetTransaction`, `GetTransactionResult`, and `GetTransactionResultPdf` methods for working with order transactions. New types `GetOrderTransactionResponse` and `OrderSummary` are also available, along with a `Bytes` pointer helper and a new `ClientFacingSleepCycleSourceTypeInsulinPump` source type constant.
