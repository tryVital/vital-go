## v2.0.0 - 2026-04-09
* The `GetWheelchairUse()` accessor method has been removed from both `ClientFacingActivity` and `ClientFacingProfile`. Callers that reference these methods must be updated — access the `WheelchairUse` field directly on the struct instead (e.g., `obj.WheelchairUse`).
* The SDK now supports three new query expression types: `DerivedReadinessColumnExpr` for derived readiness data columns, `AwakeningsValueMacroExpr` for awakenings value macros, and `InsulinInjectionTimeseriesExpr` as a dedicated first-class timeseries expression (previously available only as an `IntervalTimeseriesExpr` variant). The `AggregateExprArgVisitor`, `QueryGroupByItemVisitor`, and `QuerySelectItemVisitor` interfaces have been extended with new `VisitDerivedReadinessColumnExpr`, `VisitAwakeningsValueMacroExpr`, and `VisitInsulinInjectionTimeseriesExpr` methods — existing implementations of these interfaces must add these methods to compile. Additionally, `IntervalTimeseriesExprTimeseriesInsulinInjection` has been removed; use `InsulinInjectionTimeseriesExpr` instead, and the public `GetPlaceholder()`/`SetPlaceholder()` methods on `Placeholder` have been removed.
* **Breaking changes** to `ParsingJob` and `ResultMetadata` types:
* `ParsingJob.JobId` (and its `GetJobId()`/`SetJobId()` methods) has been removed. References to this field must be deleted.
* `BodyCreateLabReportParserJob.File` changed from `io.Reader` to `[]io.Reader`; callers must update to pass a slice of readers.
* `ResultMetadata` fields `PatientFirstName`, `PatientLastName`, `Dob`, and `LabName` changed from `string` to `*string`; their getter methods now return `*string` and their setter methods now accept `*string`.
* New additions include the `ParsingJobFailureReason` enum (values: `invalid_input`, `low_quality`, `not_english`) exposed via a new `FailureReason` field on `ParsingJob`, and the `ResultMetadataGender` enum (values: `male`, `female`, `other`) exposed via a new `Gender` field on `ResultMetadata`.
* The SDK now supports Sonora Quest as a new lab and appointment provider (`AppointmentProviderSonoraQuest`, `ClientFacingLabsSonoraQuest`). New optional fields have been added across several request and response types: appointment notes on `AppointmentBookingRequest`, `AppointmentRescheduleRequest`, and `RequestAppointmentRequest`; async booking confirmation controls on `AppointmentBookingRequest`; `OrderTransactionId` filtering on `LabTestsGetOrdersRequest` and `ClientFacingAppointment`; `LabSlug` on `LabTestsGetMarkersRequest`; `AllowStale` on `LabTestsGetPscAppointmentAvailabilityRequest`; `AccessNotes` on `PatientAddress` and `UsAddress`; and `LabAccountId`/`LabSlug` on `CreateLabTestRequest`. A new `LabTestsBookPscAppointmentRequest` struct is available for PSC appointment booking with idempotency key support. `AppointmentPscLabs` is now a proper typed enum with named constants and constructor/pointer helpers.
* Several breaking changes have been made to bulk operation request structs. The `TeamId` field and `SetTeamId` method have been removed from `BulkExportConnectionsBody`, `BulkImportConnectionsBody`, `BulkPauseConnectionsBody`, `BulkTriggerHistoricalPullBody`, and `LinkListBulkOpsRequest`. The associated types `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` have also been removed — callers must remove any references to these fields and types.
* New additions include `ManualProvidersSamsungHealth` and `PasswordProvidersTandemSource` provider constants, a `RecoveryReadinessScore` field on `ClientFacingSleep` (sourced from Oura, Whoop, and Ultrahuman), and new `VitalIosSdkVersion`, `VitalAndroidSdkVersion`, and `GrantedPermissions` fields on `ManualConnectionData`.
* The SDK now includes support for lab report parsing job webhook events (`ClientFacingLabReportParsingJobCreatedEvent`, `ClientFacingLabReportParsingJobUpdatedEvent`), a rich set of lab result types (`BiomarkerResult`, `LabResultsRaw`, `SampleData`, `PerformingLaboratory`, etc.), and order transaction tracking (`ClientFacingOrderTransaction`, `ClientFacingOrderInTransaction`). `ClientFacingOrder` gains `LastEvent`, `ClinicalNotes`, `Origin`, and `OrderTransaction` fields, and `Address` / patient address types now include an optional `AccessNotes` field. New enum values have been added to `Labs`, `PayorCodeExternalProvider`, and `Providers`.
* Several breaking changes are included in this release:
* The `Address` field on `UserInfo` and `UserInfoCreateRequest` now uses the new `*UserAddress` type instead of `*Address`. Update any references accordingly — `UserAddress` exposes the same fields.
* `UserRefreshSuccessResponse` no longer exposes `Success` as a settable JSON field; the `GetSuccess()` and `SetSuccess()` methods have been removed. Use the new `Success() bool` method to read the value.
* `BookPscAppointment` now accepts `*LabTestsBookPscAppointmentRequest` (which supports idempotency headers) instead of `*AppointmentBookingRequest`.
* `labreport.ParserCreateJob` now accepts multiple files in the `File` field (slice) instead of a single file.
* New capabilities: Three new sub-clients — `Compendium`, `LabAccount`, and `OrderTransaction` — are now available on the top-level `Client`. `ClientFacingInsulinInjectionSample` gains optional `DeliveryMode`, `DeliveryForm`, and `BolusPurpose` fields with corresponding enums. A new `ClientFacingDeviceSourceTypeInsulinPump` constant is available.
* The SDK now includes types for the lab compendium search and conversion APIs. New exported types include `SearchCompendiumBody`, `ConvertCompendiumBody`, `SearchCompendiumResponse`, `ConvertCompendiumResponse`, `CanonicalCandidate`, `PerLabCandidate`, `RelatedCandidate`, and `ProviderIdConversionResponse`, along with the `CompendiumSearchLabs` and `SearchMode` enums.
* The SDK now includes two new API client packages: `compendium` (with `Search` and `Convert` methods) and `labaccount` (with `GetTeamLabAccounts`). New types `ClientFacingLabAccount`, `GetTeamLabAccountsResponse`, `LabAccountDelegatedFlow`, `LabAccountStatus`, and `UsState` are also available. The `insulin_pump` source type has been added to the ECG and menstrual cycle source type enumerations.
* The SDK now includes a new `ordertransaction` package with a `Client` that exposes `GetTransaction`, `GetTransactionResult`, and `GetTransactionResultPdf` methods for interacting with order transaction endpoints. New types `GetOrderTransactionResponse` and `OrderSummary` have been added, along with a `ClientFacingSleepCycleSourceTypeInsulinPump` enum constant and a `Bytes` pointer helper.
