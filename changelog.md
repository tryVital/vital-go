## v2.0.0 - 2026-04-08
* The `GetWheelchairUse()` accessor method has been removed from both `ClientFacingActivity` and `ClientFacingProfile`. Callers that used these methods must update their code — either access the `WheelchairUse` field directly or remove the call if the field is no longer needed.
* Three new expression types are now supported in query operations: `DerivedReadinessColumnExpr` (with readiness metrics such as sleep score, recovery score, and strain zone), `AwakeningsValueMacroExpr`, and `InsulinInjectionTimeseriesExpr` (replacing the former `IntervalTimeseriesExprTimeseriesInsulinInjection` constant).
**Breaking changes:** The `AggregateExprArgVisitor`, `QueryGroupByItemVisitor`, and `QuerySelectItemVisitor` interfaces each have three new required methods (`VisitDerivedReadinessColumnExpr`, `VisitAwakeningsValueMacroExpr`, `VisitInsulinInjectionTimeseriesExpr`). Any existing implementation of these interfaces must add these methods or it will no longer compile. Additionally, `IntervalTimeseriesExprTimeseriesInsulinInjection` has been removed from the `IntervalTimeseriesExprTimeseries` enum; use the new `InsulinInjectionTimeseriesExpr` type instead. The `Placeholder.GetPlaceholder()` method and `SetPlaceholder()` setter have been removed in favour of a `Placeholder()` accessor that reflects the field's new literal-constant semantics.
* **Breaking changes to lab report types:**
* `ParsingJob.JobId` field, `GetJobId()`, and `SetJobId()` have been removed with no direct replacement. A new `FailureReason` field (`*ParsingJobFailureReason`) has been added along with a `ParsingJobFailureReason` enum (`invalid_input`, `low_quality`, `not_english`).
* `ResultMetadata` fields `PatientFirstName`, `PatientLastName`, `Dob`, and `LabName` have changed from required `string` to optional `*string`. Callers must dereference these values and guard against `nil`. A new optional `Gender` field (`*ResultMetadataGender`) has been added with an accompanying enum type.
* `BodyCreateLabReportParserJob.File` has changed from `io.Reader` to `[]io.Reader`, allowing multiple files to be submitted in a single request.
* The SDK now supports Sonora Quest as an appointment provider and lab (`AppointmentProviderSonoraQuest`, `ClientFacingLabsSonoraQuest`). New fields have been added across lab testing types including appointment notes, async booking confirmation controls, order transaction ID filtering, lab slug filtering for markers, clinical notes on orders, and access notes on address types. A new `LabTestsBookPscAppointmentRequest` struct with idempotency key support is now available for PSC appointment booking.
**Breaking change:** Several types previously exported from the lab testing package have been removed: `BiomarkerResult`, `ClinicalInformation`, `FailureType`, `LabResultsMetadata`, `LabResultsRaw`, `LabResultsRawResults`, `MissingBiomarkerResult`, `OrderLowLevelStatus`, `ParentBiomarkerData`, `ResultType`, `SampleData`, `SampleDataDateCollected`, `SampleDataDateReceived`, `SampleDataDateReported`, and `UtcTimestampWithTimezoneOffset`. Additionally, `AppointmentPscLabs` has changed from a `string` type alias to a named `string` type with defined constants, which may affect code that assigns raw string values.
* The `TeamId` field and `SetTeamId` method have been removed from `BulkExportConnectionsBody`, `BulkImportConnectionsBody`, `BulkPauseConnectionsBody`, `BulkTriggerHistoricalPullBody`, and `LinkListBulkOpsRequest`. The exported types `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` have also been removed. Callers referencing these fields or types must remove those usages.
* New capabilities include a `RecoveryReadinessScore` field on `ClientFacingSleep`, new `VitalIosSdkVersion`, `VitalAndroidSdkVersion`, and `GrantedPermissions` fields on `ManualConnectionData`, and new `ManualProvidersSamsungHealth` and `PasswordProvidersTandemSource` provider constants.
* The SDK now supports lab report parsing job webhook events (`lab_report.parsing_job.created` and `lab_report.parsing_job.updated`) via new `ClientFacingLabReportParsingJobCreatedEvent` and `ClientFacingLabReportParsingJobUpdatedEvent` types. New types have been added for order transactions (`ClientFacingOrderTransaction`, `ClientFacingOrderInTransaction`) and `ClientFacingOrder` now includes `LastEvent`, `ClinicalNotes`, `Origin`, and `OrderTransaction` fields. Addresses now support an optional `AccessNotes` field, order events include an optional `StatusDetail` field, and new biomarker-related types (`BiomarkerResult`, `MissingBiomarkerResult`, `LabResultsRaw`, `SampleData`, etc.) are available for richer lab result handling.
* Several breaking changes are included in this release:
* `UserInfo.Address` and `UserInfoCreateRequest.Address` now use the new `*UserAddress` type instead of `*Address`. Update any code that constructs or reads these fields.
* `UserRefreshSuccessResponse.GetSuccess() bool` has been removed and replaced with `Success() bool`; callers must update their method calls accordingly.
* `BookPscAppointment` now accepts `*LabTestsBookPscAppointmentRequest` instead of `*AppointmentBookingRequest`.
* `ParserCreateJob` now accepts a slice of files rather than a single file.
* New capabilities also included: three new sub-clients (`Compendium`, `LabAccount`, `OrderTransaction`) are available on the top-level client; `ClientFacingInsulinInjectionSample` gains `DeliveryMode`, `DeliveryForm`, and `BolusPurpose` fields; and a new `ClientFacingDeviceSourceTypeInsulinPump` constant has been added.
* The SDK now includes types for compendium search and lab test conversion. New structs `SearchCompendiumBody`, `ConvertCompendiumBody`, `SearchCompendiumResponse`, and `ConvertCompendiumResponse` are available, along with supporting types `CanonicalCandidate`, `PerLabCandidate`, `RelatedCandidate`, and `ProviderIdConversionResponse`. Two new enums, `CompendiumSearchLabs` and `SearchMode`, are also introduced.
* The SDK now includes two new API client packages: `compendium` (with `Search` and `Convert` methods) and `labaccount` (with `GetTeamLabAccounts`). New types `ClientFacingLabAccount`, `GetTeamLabAccountsResponse`, `LabAccountDelegatedFlow`, `LabAccountStatus`, and `UsState` are available in the top-level package. The `insulin_pump` source type is now recognized in ECG and menstrual cycle source type enums.
* The SDK now includes a new `ordertransaction` package with a `Client` that exposes `GetTransaction`, `GetTransactionResult`, and `GetTransactionResultPdf` methods for retrieving order transaction details and lab results. New supporting types `GetOrderTransactionResponse` and `OrderSummary` have been added, along with a new `ClientFacingSleepCycleSourceTypeInsulinPump` source type constant and a `Bytes` pointer helper function.
