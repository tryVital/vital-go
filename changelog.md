## v2.0.0 - 2026-04-09
* The `GetWheelchairUse()` accessor method has been removed from both `ClientFacingActivity` and `ClientFacingProfile`. Callers that use these methods must migrate to direct field access via `obj.WheelchairUse`, adding a nil pointer guard where necessary.
* The SDK now supports three new query expression types: `DerivedReadinessColumnExpr` (for readiness-related columns including sleep score, recovery score, strain, and stress), `AwakeningsValueMacroExpr` (for querying awakenings value macros), and `InsulinInjectionTimeseriesExpr` (for insulin injection timeseries data, replacing the former `insulin_injection` variant in `IntervalTimeseriesExpr`). The visitor interfaces `AggregateExprArgVisitor`, `QueryGroupByItemVisitor`, and `QuerySelectItemVisitor` have each gained three new required `Visit*` methods; existing implementations must add `VisitDerivedReadinessColumnExpr`, `VisitAwakeningsValueMacroExpr`, and `VisitInsulinInjectionTimeseriesExpr` to continue compiling. Additionally, `Placeholder.GetPlaceholder()` and `SetPlaceholder()` have been removed in favor of the new `Placeholder()` accessor method.
* **Breaking changes to `ParsingJob` and `ResultMetadata` types.**
* `ParsingJob.JobId` (and its `GetJobId()`/`SetJobId()` methods) has been removed. Remove any references to this field.
* `BodyCreateLabReportParserJob.File` changed from `io.Reader` to `[]io.Reader`; update callers to pass a slice.
* `ResultMetadata` fields `PatientFirstName`, `PatientLastName`, `Dob`, and `LabName` changed from `string` to `*string`; dereference the pointer and handle `nil` where these are used. The corresponding setter methods now accept `*string`.
* New capabilities also included in this release: `ParsingJob` now exposes a `FailureReason` field of the new `ParsingJobFailureReason` enum type (`invalid_input`, `low_quality`, `not_english`), and `ResultMetadata` now includes a `Gender` field of the new `ResultMetadataGender` enum type (`male`, `female`, `other`).
* The SDK now supports Sonora Quest as a new lab provider (`AppointmentProviderSonoraQuest`, `ClientFacingLabsSonoraQuest`). Several new fields have been added across the lab testing API: `AppointmentBookingRequest` gains async confirmation controls and appointment notes; `CreateLabTestRequest` gains `LabAccountId` and `LabSlug`; `CreateOrderRequestCompatible` gains `ClinicalNotes`; `ClientFacingAppointment` gains `OrderTransactionId` and `AppointmentNotes`; `PatientAddress` and `UsAddress` gain `AccessNotes`; and new filter fields (`LabSlug`, `OrderTransactionId`, `AllowStale`) have been added to various query request types. The `AppointmentPscLabs` type has been promoted from a string alias to a named enum type with typed constants. Several internal result and metadata types (`BiomarkerResult`, `ClinicalInformation`, `LabResultsMetadata`, `LabResultsRaw`, `MissingBiomarkerResult`, `ParentBiomarkerData`, `PerformingLaboratory`, `SampleData`, `UtcTimestampWithTimezoneOffset`, and related types) have been removed from the public API.
* Several breaking changes have been made to bulk operation request types. The `TeamId` field and `SetTeamId` method have been removed from `BulkExportConnectionsBody`, `BulkImportConnectionsBody`, `BulkPauseConnectionsBody`, `BulkTriggerHistoricalPullBody`, and `LinkListBulkOpsRequest`. The exported types `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` (and their associated constructors and constants) have also been removed. Callers referencing these fields or types must remove those usages.
* The SDK also adds new capabilities: `ManualProvidersSamsungHealth` and `PasswordProvidersTandemSource` provider constants, a `RecoveryReadinessScore` field on `ClientFacingSleep`, and new `VitalIosSdkVersion`, `VitalAndroidSdkVersion`, and `GrantedPermissions` fields on `ManualConnectionData`.
* The SDK now exposes new types and fields for richer lab results, order management, and address handling:
* New `BiomarkerResult`, `MissingBiomarkerResult`, and `LabResultsRaw` types provide structured access to lab result data including reference ranges, LOINC codes, and performing laboratory details.
* New webhook event types `ClientFacingLabReportParsingJobCreatedEvent` and `ClientFacingLabReportParsingJobUpdatedEvent` are available for lab report parsing job notifications.
* `ClientFacingOrder` gains `ClinicalNotes`, `LastEvent`, `Origin`, and `OrderTransaction` fields; new `ClientFacingOrderTransaction` type exposes order transaction lifecycle data.
* `Address`, `PatientAddressCompatible`, and `PatientAddressWithValidation` now include an `AccessNotes` optional field.
* `ClientFacingOrderEvent` gains a `StatusDetail` field backed by the new `OrderStatusDetail` enum.
* New enums: `OrderLowLevelStatus`, `OrderOrigin`, `OrderTransactionStatus`, `ResultType`, and additional `Labs` constants (`SonoraQuest`, `CRL`).
* The SDK now includes types for lab compendium search and conversion. New types `SearchCompendiumBody`, `SearchCompendiumResponse`, `ConvertCompendiumBody`, and `ConvertCompendiumResponse` are available, along with supporting types (`CanonicalCandidate`, `PerLabCandidate`, `RelatedCandidate`, `ProviderIdConversionResponse`) and enums (`CompendiumSearchLabs`, `SearchMode`) for working with cross-lab provider ID mapping and LOINC-based test search.
* The SDK now includes two new API clients: `compendium` (with `Search` and `Convert` methods) and `labaccount` (with `GetTeamLabAccounts`). New types `ClientFacingLabAccount`, `GetTeamLabAccountsResponse`, `LabAccountStatus`, `LabAccountDelegatedFlow`, and `UsState` are also available. Additionally, `insulin_pump` has been added as a valid source type for electrocardiogram and menstrual cycle resources.
* The SDK now includes a new `ordertransaction` package with a `Client` that exposes `GetTransaction`, `GetTransactionResult`, and `GetTransactionResultPdf` methods for the `/v3/order_transaction` endpoints. Two new types, `GetOrderTransactionResponse` and `OrderSummary`, are available in the root package, along with a new `ClientFacingSleepCycleSourceTypeInsulinPump` source type constant and a `Bytes` pointer helper.
